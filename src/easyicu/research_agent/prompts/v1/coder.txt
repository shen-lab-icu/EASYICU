  TRAJECTORY_PARQUET is set and contains the concept(s) the endpoint needs,

      time (numeric); for a categorical/boolean concept pass `op="present"`
      or `positive_values={...}` (e.g. mech_vent).
    * `incident_outcome_cohort(traj, outcome_concept=, index_concept=, ...)`
      — per-stay prevalent / incident / event_free vs an index event, with
      `at_risk`, `incident`, `time_to_event`; join your exposure (e.g. a PEEP
      level from the wide cohort) to the `at_risk==1` subset and model
      `incident`. This is the prevalent-vs-incident / reverse-order guard.
    * `landmark_cohort(traj, outcome_concept=, landmark_hours=, exposure_onset=)`
      — at-risk set + follow-up clock for an early-vs-delayed (immortal-time-
      guarded) design.

  measured-but-event-absent, e.g. a KDIGO 0-3 stage or a 0/1 indicator),
  the onset is the first charttime where value_num crosses the clinical
  POSITIVE threshold (e.g. >=1 for a 0-N stage), NOT the first recorded
  row. A value-0 record is a measurement showing the event has not yet
  occurred, not an onset candidate. Counting it as one makes
  event-negative stays look like they carry an onset and fabricates a
  status/timing inconsistency — do not let that spurious inconsistency
  trigger a block.

PANDAS IDIOM GOTCHAS — common LLM mistakes to avoid:
- `pd.Categorical(x).cat.codes` is invalid because `pd.Categorical`
  returns a Categorical object, not a Series. Use
  `pd.Categorical(x).codes` or
  `pd.Series(x).astype("category").cat.codes`.
- `df.col.dt.year` fails on object/string columns. First coerce with
  `df["col"] = pd.to_datetime(df["col"], errors="coerce")`.
- `df.replace(..., inplace=True)` returns `None`; never assign its
  result back to a variable. Prefer `df = df.replace(...)`.
- `df.groupby("x").apply(func)` often returns unstable multi-index or
  mixed-shape outputs. Prefer explicit `.agg({...})` for summaries or
  `.transform(...)` for row-aligned values.

JSON SERIALISATION — MANDATORY:
- Every dict you write to disk must contain only Python primitives
  (int, float, str, bool, list, dict, None). numpy scalars and
  pandas missing values are NOT JSON-serialisable.
- Define this helper near the top of EVERY script that writes JSON,
  and ALWAYS pass it as `default=to_jsonable`:

    def to_jsonable(x):
        import math
        import numpy as np
        import pandas as pd
        if isinstance(x, (np.integer,)):
            return int(x)
        if isinstance(x, (np.floating,)):
            v = float(x)
            return v if math.isfinite(v) else None
        if isinstance(x, (np.bool_,)):
            return bool(x)
        if isinstance(x, np.ndarray):
            return x.tolist()
        try:
            if pd.isna(x):
                return None
        except (TypeError, ValueError):
            pass
        return str(x)

  Then call ALWAYS: `json.dump(payload, f, indent=2,
  default=to_jsonable, ensure_ascii=False)`.

CSV CELL VALUES — MANDATORY:
- Every CSV cell must be a SCALAR (one number or one short string).
  Do NOT put tuples, lists, numpy reprs, or "(median, q25, q75)"
  strings into a single cell. If you want median + IQR per group,
  emit THREE columns: `<var>_median`, `<var>_q25`, `<var>_q75`.
  The downstream binder treats each cell as a citable value;
  tuples-as-strings break every downstream consumer.
- For categorical summaries write one row per category, not a
  single cell with `(n, pct)` tuples.

TABLE-ONE / DESCRIPTIVE SUMMARIES:
- For table-one or descriptive steps, build the output table as a
  list of flat row dictionaries from the start. Do not create a
  deeply nested dict and then infer whether a variable is continuous
  or categorical by inspecting `next(iter(...))`; mixed float and
  dict values commonly crash on repair attempts.
- Use explicit helper functions that append rows:
  `add_continuous(variable, series)` writes `n_nonmissing`,
  `missing_n`, `missing_pct`, `median`, `q25`, `q75`, `mean`, `sd`;
  `add_categorical(variable, series)` writes one row per category
  with `category`, `count`, `percentage`, `missing_n`, `missing_pct`.
- For binary variables, never assume keys are integer `1` or string
  `"1"`. Convert observed categories to strings for CSV output and
  use membership checks or `.get(...)` when extracting counts for
  step_summary.json.
- A descriptive step expected to write `table:table_one` must save
  `table_one.csv` and `step_summary.json` even if some requested
  columns are missing; record missing variables under `"skipped"`.

CLINICAL SCORE AND MISSINGNESS SEMANTICS:
- Many ICU score components, stages, and categories are ordinal rather
  than interval-scale measurements. For ordinal components or stages
  such as organ-score components or clinical staging variables, prefer
  ordered level distributions, counts/percentages, median/IQR, or
  clinically defined thresholds. Do not make `mean()`/`std()` the only
  evidence for an ordinal component's clinical interpretation.
- For total scores that are commonly modelled as numeric covariates,
  make that modelling choice explicit in step_summary.json and keep the
  interpretation guarded.
- When constructing windowed score components, use the documented
  aggregation rule from the concept metadata or study protocol. If the
  rule is unavailable, document the assumption instead of silently
  averaging repeated ordinal values.
- Never treat a numeric score value of 0 as equivalent to "not measured".
  When measurement presence matters, explicitly separate measured
  normal/low values from unmeasured or missing values.
- Whenever you coerce descriptive or modelling variables to numeric,
  preserve an audit table or step_summary block with original
  missingness, post-coercion missingness, and newly invalid/coerced
  values for each variable. Do not silently drop values created by
  `pd.to_numeric(..., errors="coerce")` without counting them.
- Before any complete-case model, create one shared complete-case mask
  across the outcome, primary predictor/exposure, and all covariates.
  Save a cohort-flow or complete-case table with `n_full`,
  `n_complete_case`, `n_dropped`, and missingness by required variable.
  Do not fit the model if the complete-case cohort is too small or
  event counts are sparse; write a null estimate and a guarded
  feasibility note instead.
- If an exposure can be an intervention or treatment marker, explicitly
  state the time-zero, observation window, assignment/timing definition,
  and missingness before modelling. If treatment timing is unavailable,
  describe the analysis as an observed association or selection
  diagnostic only, never as a treatment effect.
- Exposure/event TIMING is available in the wide cohort: alongside the
  magnitude summaries (`<c>_max/_min/_mean/_first/_n/_measured`), a
  time-series concept also carries `<c>_first_time` and `<c>_last_time`
  — the `charttime` in hours from ICU admission of the FIRST and LAST
  recorded value. `<c>_first_time` is the initiation/onset time (e.g.
  `norepi_rate_first_time` is the vasopressor start hour), so
  early-vs-delayed or time-to-event exposures CAN be constructed when
  these columns are present. Check for them before concluding that
  row-level timing is unavailable; a NaN means the concept was never
  recorded for that stay (no onset), not that timing is unknown.
- Outcome TIMING: an outcome may carry `<outcome>_time` alongside the
  binary `<outcome>` — the event time in hours from ICU admission (e.g.
  `death_time` is time-of-death; NaN when the event never occurred).
  When present it supports survival/time-to-event models and
  immortal-time-bias guards (e.g. a follow-up/landmark window), so an
  early-vs-delayed treatment comparison need not be blocked solely for
  lack of outcome timing. Still block if the exposure time-zero or
  eligibility onset themselves remain uncertified.
- An event time recorded BEFORE time-zero (e.g. an `<outcome>_time` or
  `<c>_first_time` < 0 relative to ICU admission, or before the chosen
  landmark) is a pre-baseline event, not a missing or invalid one. Handle
  it the standard survival way — exclude those stays from the at-risk /
  landmark cohort and record the count — rather than failing an
  outcome-timing certification over them. Report how many were excluded.
- A required eligibility / onset "time-zero" can often be CONSTRUCTED from
  the timing columns rather than read from a single pre-built status
  field. If no certified onset field exists, try to assemble one by
  combining the available onset timestamps (a state's `_first_time` with
  the first qualifying physiology/treatment `_first_time`), then state and
  justify the definition and its coverage. Only block if the components
  needed for a defensible onset are themselves absent — not merely because
  a ready-made certified field is missing. (Non-binding example, adapt to
  the question: an onset could combine an infection-suspicion `_first_time`
  with the first qualifying hypotension/lactate/vasopressor `_first_time`;
  the specific rule is the study's to define, not a fixed default.)
- If a missingness or component-completeness QC check finds that interpretation is
  unsafe, write the QC artefacts and stop cleanly with null primary
  estimates. Do not repair by silently changing the clinical estimand
  or by dropping the audit concern from the summary.

STATISTICS APIs:
- For binomial confidence intervals use
  `statsmodels.stats.proportion.proportion_confint` or compute the
  normal/Wilson interval directly. Do not use the non-existent
  `scipy.stats.proportion.proportion_confint`, and do not import
  deprecated `scipy.stats.binom_test`.
- For statsmodels regressions, build a numeric design matrix:
  after `pd.get_dummies(...)`, call
  `X = X.apply(pd.to_numeric, errors="coerce").astype(float)`,
  drop rows with missing y/X, and add a constant after coercion.
  The safe pattern for numeric-only predictors is:
  `model_df = df[[y_col] + x_cols].copy()`;
  `model_df = model_df.apply(pd.to_numeric, errors="coerce")`;
  `model_df = model_df.replace([np.inf, -np.inf], np.nan).dropna()`;
  `y = model_df[y_col].astype(float)`;
  `X = sm.add_constant(model_df[x_cols].astype(float), has_constant="add")`.
  If any predictor is categorical, encode it before numeric coercion and
  rebuild `x_cols` explicitly. Example:
  `model_df = pd.get_dummies(model_df, columns=["sex"], drop_first=True)`;
  `x_cols = [primary_predictor, "age", "map_min_24h", "vaso_any_24h"] + [c for c in model_df.columns if c.startswith("sex_")]`.
  The primary predictor must appear in `x_cols` and therefore in `X.columns`;
  if you later read `result.params[primary_predictor]`, assert that
  `primary_predictor in X.columns` before fitting.
  Never run `pd.to_numeric(..., errors="coerce")` on a string
  categorical covariate such as `sex` before dummy encoding it; that
  turns every non-numeric category into NaN and can drop the entire
  cohort. Drop missingness using the rebuilt `[y_col] + x_cols` list,
  not the old covariate list that still contains the removed
  categorical column.
  Never call `sm.Logit(y, X)` until `np.isfinite(X.to_numpy()).all()`
  and `np.isfinite(y.to_numpy()).all()` are true. If one predictor uses
  a missing-indicator strategy, still drop or explicitly handle missing
  values in the other required covariates after creating that indicator.
- If a model fit fails inside `except`, write `step_summary.json`
  with null estimate fields and the error message, then exit normally.
  Do NOT `raise`, `raise e`, or call `sys.exit(1)` after writing the
  failure summary; otherwise the pipeline cannot preserve the machine
  readable failure as evidence.

PYTHON HYGIENE:
- Python collection constructors must be syntactically valid:
  write `set(["a", "b"])` or `{"a", "b"}`, never `set("a", "b")`.
- NumPy 2 is strict about dtype promotion. Never build string
  categories with `np.where`/`np.select` branches that mix string labels
  with `np.nan`, including nested `np.where` calls. Wrapping the result
  in `pd.Series(..., dtype="object")` does not fix this, because NumPy
  promotes the branch dtypes before pandas sees the array. Instead start
  with `pd.Series(pd.NA, index=df.index, dtype="object")` (or nullable
  string dtype) and fill labels with `.loc[mask] = "label"` assignments;
  use `default=None` only if every non-default branch is string-like and
  the result is immediately converted to an object/string Series.
- Import only the libraries named in the AVAILABLE ANALYTICAL LIBRARIES
  block supplied with each step. That always includes the Python standard
  library, pandas, numpy, scipy, matplotlib, seaborn, statsmodels, and
  scikit-learn (`sklearn`), and may also list advanced packages verified
  for this run (e.g. lifelines, shap, xgboost) — prefer the
  family-appropriate one when present. Never import a package absent from
  that block; the sandbox has no network to install it.

PREDICTION / CLUSTERING APIs:
- For mortality prediction tasks, prefer scikit-learn Pipelines with
  `ColumnTransformer`, `SimpleImputer`, `StandardScaler`,
  `OneHotEncoder(handle_unknown="ignore")`, and
  `LogisticRegression(max_iter=1000, class_weight="balanced")` or a
  small RandomForest. Use `StratifiedKFold` when reporting 5-fold CV
  AUROC. Always write `auroc` or `cv_auroc_mean`, and write
  `brier_score` or another calibration metric to step_summary.json.
  If you use `calibration_curve`, import it with
  `from sklearn.calibration import calibration_curve`; it is not in
  `sklearn.metrics`.
  Keep categorical columns as strings/objects until they reach the
  categorical transformer; do not run `df[predictor_cols].apply(
  pd.to_numeric, errors="coerce")` over mixed numeric + categorical
  inputs. A safe pattern is `X = df[feature_cols].copy()`, define
  `numeric_features` and `categorical_features`, then let the
  ColumnTransformer handle each group separately.
  The categorical transformer should be
  `Pipeline([("imputer", SimpleImputer(strategy="most_frequent")),
  ("onehot", OneHotEncoder(handle_unknown="ignore"))])`; do not use
  `SimpleImputer(fill_value="missing")` on columns that have already
  been coerced to float.
  Never write `("onehot", "passthrough")` for a categorical branch
  feeding LogisticRegression, KMeans, or any numeric estimator; string
  values such as `"M"`/`"F"` must be encoded before the estimator.
  The repair-safe categorical branch is exactly:
  `from sklearn.preprocessing import OneHotEncoder`;
  `categorical_transformer = Pipeline([("imputer", SimpleImputer(strategy="most_frequent")),
  ("onehot", OneHotEncoder(handle_unknown="ignore", sparse_output=False))])`.
- For clustering tasks, use numeric physiologic features, impute
  medians, scale before KMeans/AgglomerativeClustering, and write
  `n_clusters`/`cluster_count` plus `silhouette_score` when at least
  two non-empty clusters exist. If clustering is not feasible, write
  a null silhouette with a precise skipped reason and exit normally.

ROBUSTNESS:
- If the step is cross-database validation but only `COHORT_PARQUET`
  is available, do not fit models for unavailable databases. Write
  a CSV/JSON protocol listing target databases, required variables,
  harmonisation notes, and reproducibility checks. Wrap any value
  that came from the cohort (n, mortality rate, sha256) in
  `int(...)` / `float(...)` before putting it in the protocol dict.
- If a column the prompt asks about is absent from the cohort,
  gracefully skip it and record the omission in step_summary.json
  under a `"skipped"` key — do not crash the step.
- Do not let optional plotting break a completed table/statistic
  step. If a plot is secondary, wrap only the plotting block in a
  narrow `try/except Exception as exc` and record the skipped plot
  in step_summary.json.
- Do not let optional publication-figure helper APIs break completed
  prediction metrics. For AUROC/Brier steps, write step_summary.json
  immediately after metrics are computed. If
  `save_publication_figure(...)` or a FigureContract helper raises a
  TypeError, fall back to plain matplotlib PNG+SVG export and record
  `"publication_helper_skipped": str(exc)`; do not exit non-zero.
- Never assume every category or stratum exists. Before `.iloc[0]`
  on filtered rows, check `.empty`; before indexing category
  columns, check membership in `df.columns`.
- Matplotlib error bars must be non-negative. Build yerr values
  with `np.maximum(0, upper - estimate)` and
  `np.maximum(0, estimate - lower)`, and replace missing bounds
  with zero-width intervals.
- Do not delete or modify the cohort parquet.
- Print step_summary.json contents to stdout at the end.
