## overall information architecture & navigation model

**做得好的：**
- The sidebar's three-section lifecycle (Discovery & Plan → Data & Review → Analysis & Evidence, app.js:164/176/192) genuinely mirrors how a clinical study proceeds (idea → data → analysis/manuscript), and reserving 'Analysis & Evidence' for the evidence-gated Agent while keeping Cohort Statistics under Data & Review with the disambiguating subtitle 'groups + coverage' (app.js:93) is a defensible, coherent split between descriptive review and gated analysis.
- One-destination-one-name is explicitly engineered for the classic four: CLASSIC labels, CRUMB_LABELS, and code comments lock sidebar/breadcrumb/page-title agreement ('Labels match each screen's own page title and breadcrumb so a destination has ONE name', app.js:86-89; 'Sidebar-vs-crumb drift (患者明细 / 跨库对比) made the same screen read as three different places', app.js:111-113) — and the fix held for Patient Review/Cohort Statistics/Cross-DB Benchmark.
- The three-entry-point mental model is taught twice in matching words: the sidebar shared-note ('Paper or topic? Start with Idea Mining. Clear question? Start Guided study. Already have data? …', app.js:175) and the home page's need-phrased router ('I have a clear research question' / 'I have a paper or topic' / 'I have local ICU data', screens-extraction.js:80,104-105) with a 'Recommended' badge steering novices to Guided.
- Route hygiene is mostly excellent: unknown hashes rewrite to the home fallback (app.js:25-31), and legacy deep links #help/#assistant/#audit/#sofareclass/#icd all still resolve to the right screen with panel focus preserved and consumed exactly once (app.js:10-17; screens-viz.js:4640; screens-extraction.js:1813,2032) — old bookmarks never dead-end.
- The collapsible Data Workspace group cannot hide the user's current location: it defaults open (classicOpen = true, app.js:96) and is force-opened whenever a child route is active (wsOpen = classicOpen || classicActive, app.js:153), and collapse is not persisted across reloads, so new users always see the four destinations.
- The Demo/Real toggle is discoverable and honest: it carries a state-explaining tooltip ('Demo mode: every number on screen is a seeded example, not your data…', app.js:233), and switching with work in flight opens a confirm that promises 'Nothing already computed is deleted' (i18n.js:132-142); the home page's own toggle routes through the same canonical setDataMode so a cancelled switch never desyncs (screens-extraction.js:16-19,158-165).
- Returning users get a real re-entry point: the home 'Resume your last study' banner names the question, the destination screen, and recency ('继续上次的研究', screens-extraction.js:213-238), while first-time users get the dismissible 2-minute demo nudge (screens-extraction.js:143-148) — the router adapts to both audiences.
- Cross-screen context visibly survives navigation: the Guided→classic handoff banner surfaces the full configured design ('Cohort/Outcome/Window/Compare/Modules/Save to', app.js:65-75) instead of silently dropping it, which is exactly the reassurance a clinician needs when the app teleports them to an expert page.

**维度级结构建议：**

- Adopt 'label promises = state changes' for mode-touching CTAs: any button that says demo (Get Started 'Start demo') must set demo mode via the canonical setDataMode guard, mirroring the home first-time nudge.
- Canonicalize legacy alias hashes via the existing replaceHash path so URL, sidebar highlight, and breadcrumb always agree; keep the alias table as the compatibility layer it already is.

## first-run onboarding & local data setup journey

**做得好的：**
- The raw-data funnel inside Data Extraction is genuinely well-staged: connect ('Connect your data · local-only · nothing is uploaded', screens-extraction.js:630-666) → 'Analyze folder' with an explicit privacy promise ('We inspect filenames, manifests, and table layout only. No patient rows are uploaded or returned.', :648) → scan verdict distinguishing prepared/module/raw with cost transparency ('Convert raw files · ~2.1 GB · one-time', :762) → live per-file SSE convert progress → 'Continue to extraction'. A raw-CSV.GZ user cannot miss the conversion step on this path.
- Fail-closed honesty when the backend is unavailable: 'The local folder scan API is unavailable... this screen will not guess a real data layout' (screens-extraction.js:720) and job-continuity copy 'EasyICU did not infer a successful result' (:1244-1253) — the UI refuses to fabricate real-data state.
- Partial-conversion handling tells the user what to DO: a job ending with per-file failures renders as degraded, not success ('Conversion finished with errors', screens-extraction.js:829), with consequences and remediation ('modules that depend on the failed tables will be incomplete. Re-run conversion to retry the failed files (converted tables are skipped)', :858).
- The Demo↔Real switch is guarded when work exists, with precise consequences ('marks your current cohort, extraction and review as out-of-date... Nothing already computed is deleted', i18n.js:132-141), and flipping modes resets extraction/viz state so stale results can't bind to the wrong source (i18n.js:114-130).
- The home three-doors IA maps onboarding to what the user already has ('I have a paper or topic' / 'I have a clear research question' / 'I have local ICU data', screens-extraction.js:80-107); the local-data door lands directly in Real-mode connect, and the dismissible first-time nudge ('Try the 2-minute demo — no setup or data required', :143-148) correctly forces demo mode before the tour.
- Real extraction requires an export destination before running, with inline remediation on the disabled CTA ('Choose an export destination before extracting.' + a 'Choose export folder' button that opens and scrolls to the picker, screens-extraction.js:1144-1146, 1906-1909) — honoring the no-silent-runs invariant without dead-ending the user.
- The convert→extract→review loop closes automatically: a successful extraction registers its output as the active workspace source shared across screens (routes/jobs.py:82-93; 'This active export is shared by Patient, Cohort, Agent, and Copilot.', screens-viz.js:749), so 'confirming it worked' is one click into Patient Review; and demo-loaded Patient Review carries a prominent seeded-demo warning with a 'Use real export' escape hatch (screens-viz.js:2569-2585).
- Server-side folder pickers are clinician-friendly: Home + /Volumes shortcuts for external drives and parquet/csv hints on likely data folders (dataio.py _shortcuts, list_dir hint field), so pointing the app at a folder rarely requires typing paths.

**维度级结构建议：**
- Establish a repaint-granularity rule and enforce it: background/SSE events may only patch their owner widget (targeted innerHTML of a stable container + explicit focus restore, as screens-viz.js:232 already does) and must never call window.__euRender when the active route is not the event's owner screen; likewise never re-render an input from its own input event.
